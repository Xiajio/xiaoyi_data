## 本地自动化

- 完整后端：`python -m pytest platform/tests -q`，372 passed / 7 skipped（45.14 秒）。跳过项必须按 pytest 原因区分：本机缺少 PostgreSQL，以及 Windows 不适用的符号链接断言，不代表相关部署门禁通过。
- 前端：TypeScript、生产构建及 133 项 Vitest 通过。
- 浏览器：75 项 Playwright 通过，包含既有流程与数据构建、发布、异步导出、实验协议和对照、权限、窄屏。新增队列健康组件后再次运行数据构建与运维相关浏览器回归。
- 可复现合成对照：见 [输入哈希与结果证据](data-engine-acceptance.json)。同模型、同 80 样本训练预算、同 40 样本评估集，原始/清洗/去重/预算选择准确率 0.5/1.0/1.0/1.0。该夹具刻意包含非法标签和重复项，仅证明闭环。
- 初轮本地百万行试验：构建 416.08 秒，峰值 RSS 152,428,544 字节，1,000,000 行输出。之后样本身份一致性检查得到加强，最终代码需使用 benchmark 工具重新测量；此数值不作为 Linux/PG 容量承诺。

隔离测试目录位于 `.test-tmp/`、`.test-runs/`，均被 Git 和 Docker 构建忽略，不使用现有生产数据库。

## Linux 发布门禁

工作流 `.github/workflows/check.yml` 包含真实 PostgreSQL、SQLite→PG 保留历史夹具、完整镜像构建、空环境 Compose 启动、三个 worker 心跳，以及真实 pg_dump/pg_restore、研究包校验和 LangGraph checkpoint 恢复。CI 的结果与日志为当前提交的证据；不得引用基线 CI 作为本次改造已通过的证明。

发布仍需在目标机器完成：授权数据的 100–300 项目录试点、100 GB 成套恢复、10 并发目录读取 P95≤1 秒、真实模型联调、目标磁盘配额与离机备份检查。RPO 24 小时和 RTO 4 小时只在实际恢复演练后才成为承诺。

## 操作与兼容边界

- 启动与环境变量：[部署手册](deployment.md)。历史迁移与主键/审核/checkpoint 处理：[迁移手册](history-migration.md)。停写备份和恢复：[恢复手册](backup-recovery.md)。
- HTTP、CLI 和 MCP 共用提交函数；派生、画像、构建、挖掘、训练包与研究包打包返回后台任务。研究包 GET 只返回已完成包，尚未生成返回 409；客户端提交任务后查询状态。
- 当前行样本可扩到百万。每配方显式源资产上限 10,000；百万个独立图像文件需要后续的流式资产清单选择接口。大视频/音频/三维/代码仍保留目录与资产能力。
- 外部实验首版实现分类评估，未声称支持检测、分割和回归评估。近重复使用有界 CPU 指纹召回，不是语义真值。
- 旧任务在停旧 worker 后幂等映射到 Job。SQLite checkpoint 完整归档，历史失败任务重新发起为新 run，双向关联旧记录且不继承下载/发布批准。
- 分阶段开放：先在隔离恢复副本验收 M0，再核对 M1 历史审核与约束；停旧 worker 后开放 M2；试点批准资产验证 M3，再开放 M4/M5。首轮保留所有旧结构与映射；回退恢复到新库与新资产位置，不删除原库，不直接覆盖上线后新增记录。
