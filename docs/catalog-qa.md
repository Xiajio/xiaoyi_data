# 数据目录问答

工作台的“数据问答”用于询问已经收集到本地目录的数据集及采集情况。它不是独立页面，而是顶栏“数据问答”按钮打开的右侧折叠面板，浏览任何工作台页面时都可以展开使用。它支持连续追问、私有会话历史、执行状态、取消和有限重试；回答带有查询时保存的来源快照、引用原文与取证时间。

## 可以询问什么

- 目前收集了多少数据集？今天新增了多少个数据集和版本？
- 最近一次 HF 采集处理了多少条？有哪些失败，之后是否重试成功？
- 每日同步的范围是什么，下次何时执行？
- 目录中有哪些图像数据集，哪些许可分类还未知？
- 某个数据集的指定版本有什么来源证据？哪些文件已经登记，有没有实测内容报告？

问答访问本地已有记录，不进行互联网搜索，也不触发采集、下载或审批。数据文件尚未取得时，只能讨论来源元数据；来源自报的行数、模态和许可并非实测或人工核验结果。旧版本回答读取其自身的不可变元数据与绑定证据，不使用最新目录信息补造历史内容。

## 启用

复用科研任务的兼容 Chat Completions 模型配置：`XIAOYI_LLM_BASE_URL`、`XIAOYI_LLM_MODEL`、`XIAOYI_LLM_API_KEY`。配置须同时注入 API 和 worker，修改后重启两者。BASE_URL 包含 API 前缀，例如 `/v1`。密钥不进入浏览器、Git 仓库或聊天问题。部署方法见 [部署说明](deployment.md)。

未配置或配置格式不正确时，页面显示“配置模型后即可开始问答”，保留当前页面内的草稿，并展示直接读取的目录统计；该统计明确标为非模型回答。配置完整只表示字段可用，实际连通性和模型兼容性仍需提问验证。HF 采集不受模型配置影响。

## 执行与证据

每个问题最多调用模型 3 次、只读查询工具 6 次。智能体先选择确定性查询工具，再根据返回记录整理回答。允许的工具只有目录概况、采集记录/计划、目录筛选和指定版本详情，不开放 SQL、任意代码、网络请求或写入业务操作。

会话仅当前账号可读取和操作，包括 reader 账号。每轮提交带幂等请求标识；同一会话同时只允许一个问题运行，最多保存 100 个问题。新问题带入最近 6 轮已完成历史和有限来源标识帮助定位追问对象；历史答案不能代替本次证据。

执行在现有单 worker 中完成，每次循环优先处理一个问答，再继续采集等任务。已开始的采集不会被强行中断，因此仍可能排队。规划、工具进度、来源快照和调用预算持久化；中断后可恢复，最多两次执行尝试。取消后的迟到模型响应不会发布答案。外部模型请求中断仍可能计费，不能保证供应商只收费一次。

每条事实陈述必须引用本轮来源 ID 与实际存在的非空原文，否则整轮回答失败。引用存在性校验不等于语义完全正确，界面明确显示“模型归纳，未经人工确认”。未知、截断、抽样与证据不足单独列出；人工核验仍需在对应工作台完成。

来源有长度和数量限制，每轮最多 24 条、序列化后 36,000 字符；整体模型上下文最多 65,000 字符；单个文档、卡片、文件和报告列表也有界限。引用中的旧记录是回答时快照，后续目录更新不会改写该轮答案。此功能不把目录信息完整度当作数据内容质量，也不把采集完成当作所有原始数据文件已下载。

## 接口

- `GET /api/qa-capabilities`：模型配置状态、预算与只读工具名称，不返回密钥或地址。
- `GET/POST /api/qa-conversations`：当前账号的会话列表与创建。
- `GET /api/qa-conversations/{id}`：该账号的会话及问题历史。
- `POST /api/qa-conversations/{id}/turns`：提交问题与 `request_key`，返回排队状态。
- `POST /api/qa-turns/{id}/cancel`、`/retry`：取消或预算内重试。

迁移 `0006_catalog_qa` 添加会话与问答记录，不改写既有目录。升级前按现有部署流程备份数据库；备份包含私有问答内容，应与团队目录一样受控保存。
