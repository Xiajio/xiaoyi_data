# 科研试点评估：目录检索与事实证据

本工具只计算已经取得并由人工标注的结果，不联网、不调用模型、不下载数据，也不证明来源许可或研究包完整性。随附模板是待执行的试点设计，所有未执行排名和未标注结果均为 `null`，不代表已完成真实评估。

## 试点准备与四个目标

使用 `docs/pilot-template.json` 建立一份独立的标注文件。冻结同一批 **100–300 个目录条目**，建议首次取 200 个，保存目录时间与 manifest SHA-256。基线与智能体必须面对同一版本目录、目标及硬约束。模型地址、密钥、模型名称和 worker 配置完成后，才能执行真实智能体任务。

| 模态 | 科研目标 | 至少一个小样本研究包的检查 |
| --- | --- | --- |
| 文本 | 中文新闻分类，有类别标注及训练/测试说明 | 读取文本和标签，检查缺失、重复与切分重叠 |
| 表格 | 监督学习基准，有明确目标列、字段定义和缺失值信息 | 加载列结构、核对目标列与缺失值，记录划分方式 |
| 图像 | 图像分类，有类别定义、格式尺寸与许可依据 | 读取授权图像样本与标签，检查损坏文件和缩略图 |
| 三维 | 三维对象分类，有类别映射与坐标/单位说明 | 读取 OBJ、PLY 或 glTF 小样本，区分几何检查与文件头声明 |

每类至少选择一个已核验许可、经人工批准获取的真实小样本，完成下载后再冻结并批准研究包。记录授权依据、快照编号和包哈希；在干净环境验证全部文件哈希及 Python 加载。将实际验证记录填入 `sample_bundle`，不能仅因评估脚本成功就填写验证通过。工具不会据这些自报字段宣布科研试点成功。

## 标注格式

每个任务包含 `task_id`、`modality`、`goal`、`relevance_labels`、`relevance_complete` 和 `methods`。`methods` 必须显式包含 `baseline` 与 `agent`。

- `ranking: null`：此方法尚未执行或结果尚未记录。`ranking: []`：已执行，确实返回零个候选。非空数组按原始排名保存 **数据集版本 ID**，不能使用可漂移的数据集名称代替。不要只保留正确结果。
- `relevance_labels`：同一任务共享的人工相关性标签，格式为 `{"dataset_version_id": 12, "relevant": true}`。`false` 表示人工判定不相关，`null` 表示待判定；缺少这一版本的记录也属于未标注。
- `relevance_complete: true`：只有已穷尽并标注预先规定的相关集合后才能设置。若只判断两种方法的候选池，Recall 只能解释为对这个冻结候选池的召回率，不能宣称对互联网全部数据集的召回率。默认保持 `false`。
- `facts`：逐条拆分事实，不将“适合本课题”等模型推断当作事实。每条包含 `fact_id`、`dataset_version_id`、`text`、`evidence_ids` 和 `supported: true/false/null`。人工对照该版本证据检查许可、行数、标签、切分等断言；引用存在但不能支持断言时标 `false`。`true` 必须有至少一个可定位证据 ID。

格式示例（仅说明字段，下面不是试点评估数据）：

```json
{
  "ranking": [12, 18],
  "facts": [
    {
      "fact_id": "claim-1",
      "dataset_version_id": 12,
      "text": "来源声明采用 MIT 许可",
      "evidence_ids": [105],
      "supported": null
    }
  ]
}
```

同一排名、同一任务的相关性标签、同一方法的事实 ID、事实内部证据 ID 不得重复。数值 `12` 与字符串 `"12"` 视为同一 ID。重复或非法标签会使工具报错；缺失/待定标签会在报告中列出，并保留无法判定的指标为 `null`。

建议先打乱并隐藏方法名称再标注，记录审核人及标注规则版本；争议项保持 `null`，待第二位审核人员裁决。不要由生成候选的模型替代人工提供真值。

## 指标定义

所有检索指标截取前 5 个返回结果。Precision@5 固定使用 5 个槽位为分母；返回少于 5 个也除以 5，报告另列 `returned`。未返回的槽位没有推荐项，不等同于将未标注候选判为不相关。

- **Hit@5**：前五中至少一个人工确认相关结果为 1。没有正例且前五全部已判定时为 0；仍有未判定候选时为 `null`。已有明确正例时，其他未判定项不会影响 Hit=1 的结论。
- **Precision@5**：前五相关数 / 5。前五返回项有任何未标注标签时返回 `null`。已执行但没有返回结果且存在人工相关性标注时为 0；未执行或完全没有人工标注时保持 `null`。
- **Recall@5**：前五相关数 / 已完整标注范围内的全部相关数。要求 `relevance_complete=true`、相关集合完整、排名内无缺失标签且分母大于零；否则为 `null`。
- **事实证据准确率 `accuracy`**：获人工确认支持的事实数 / 全部事实数。没有事实或存在未决标签时为 `null`。另报 `judged_accuracy`（仅已判定事实）和 `annotation_coverage`，不得把前者当作完整准确率。

摘要的检索指标按任务宏平均，逐项附 `evaluated_tasks/total_tasks`；事实证据指标按事实总数汇总。`null` 不填零，也不进入平均值。比较两种方法时，先核对可评估任务集合和覆盖率是否一致；工具不自动生成“智能体优于基线”的结论。四个任务用于发现问题，不能据此推广统计显著性。

## 离线执行与验收

在已安装本项目 Python 包的环境中，从仓库根目录执行：

```powershell
python -m xiaoyi_catalog.evaluation --input docs/pilot-template.json --output output/pilot-evaluation.json
```

完整标注时，把 `--input` 替换为团队维护的标注文件。输出不能覆盖输入文件。相同输入会生成字节一致的结果，没有运行时间戳、随机值或网络依赖。

```powershell
platform/.venv/Scripts/python.exe -m pytest platform/tests/test_evaluation.py -q
```

准备完成的验收包括：四个真实科研任务、100–300 个冻结目录条目、两种方法的原始排名、可定位的事实与人工标签、每类至少一个授权小样本研究包、干净环境加载记录。模型配置、真实排名、人工标注或研究包核验尚未完成时，保持模板空值并在报告中说明待办，不把示例数据当作成果。
