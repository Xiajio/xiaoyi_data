# Hugging Face 采集与定时同步

工作台左侧的 **HF 采集** 可直接提交采集任务，不需要模型 API。后台获取 Hugging Face 的元数据和数据卡片，固定版本证据，再生成结构摘要与目录信息完整度候选。候选仍需人工核验；目录信息完整度不代表实际数据内容质量。

## 一键采集

1. 打开 HF 采集，按需填写关键词、作者、语言、任务标签；默认每次最多 50 条，可改为 1–300 条。
2. 点击“立即采集”。接口返回持久任务，worker 在后台执行；关闭页面不会取消。
3. 选择任务查看采集、规则整理阶段及已处理、新增、更新、重复、失败数量。网络请求完成前可能停留在当前条目；界面不会虚构百分比。目录页、详情与卡片请求设置超时和重试预算，超时记录为失败；目录采集只请求必要元数据，不展开完整文件列表。
4. 查看逐项失败分类和事件；点击版本编号查看该次采集的固定版本证据。整理候选可在“核验工作台”人工处理。

范围按 HF 最近更新时间倒序获取，数量限制包含重复项。每日 50 条是有限范围同步，不承诺遍历整个 Hugging Face；建议为研究领域设置关键词、作者或标签。重复采集相同 revision 不产生重复版本。只采集目录和卡片，数据文件及用于内容分析的样本仍走独立下载审批。

## 每日自动同步

人工审核员或管理员可保存同步计划。默认频率每天一次、每次最多 50 条，计划表单初始暂停，保存并启用后生效。计划显示服务器保存的下次执行时间，按浏览器当地时区展示；“每天”表示从保存或重新启用时起每 24 小时。

API 与 worker 必须使用同一数据库；worker 持续运行才会触发。计划保存在数据库，重启后仍存在；错过多个周期时合并为一次派发，下次从派发时间重新计算。相同范围已有排队或运行任务时合并执行，单 worker 串行处理可能使实际开始时间晚于计划时间。

暂停只影响后续触发，已排队任务可单独取消。运行任务收到取消请求后，会等待当前请求到达安全边界再停止；已采集的版本保留。

## 失败与恢复

失败原因包含来源限流、访问权限、请求超时、网络错误和其他采集错误。界面及事件保留可定位的来源标识与安全提示，不记录原始凭据或带密钥的错误文本。部分来源失败时任务标为“部分完成”；已成功采集的版本仍可核验。

任务进度逐项保存，worker 重启后继续未完成任务；自动恢复最多 3 次，超过后需要人工重试。手动重试生成关联原任务的新记录，保留审计历史；优先重试原失败条目的固定 revision，复用成功版本，原范围未达到上限时才补充来源列表。只有规则整理失败时复用原版本，不重新采集网络来源。任务发起者可取消或重试自己的任务，人工审核员和管理员可以处理团队任务；只读成员不能提交采集。定时计划仅由人工审核员或管理员维护。

## API 与后续 LLM 接入

- `POST /api/collection-jobs`：提交范围（search、author、languages、task_categories、limit）。
- `GET /api/collection-jobs`、`GET /api/collection-jobs/{id}`：列表和状态。
- `GET /api/collection-jobs/{id}/events?after_id=0`：事件，支持按 ID 增量读取。
- `POST /api/collection-jobs/{id}/cancel`、`POST /api/collection-jobs/{id}/retry`：取消和重试。
- `GET/POST /api/collection-schedules`、`POST /api/collection-schedules/{id}`：读取、新建和修改计划。
- `GET /api/dataset-versions/{id}/evidence`：精确版本的证据。

任务保存 `dataset_version_ids`、规则整理状态、来源范围和逐项事件。后续 LLM 分析分类可基于这些固定版本与证据产生独立候选，使用已有科研任务预算、模型用量和人工核验机制。当前同步流程不调用 LLM，规则结果不会标记为模型分析或人工确认。

本地启动及环境变量见 [部署说明](deployment.md)。
网络配置沿用 Hugging Face SDK 的代理、证书与请求钩子，使用其 [HTTP 客户端配置接口](https://huggingface.co/docs/huggingface_hub/main/package_reference/utilities)。新旧 SDK 的排序参数差异通过适配与真实签名回归覆盖。
